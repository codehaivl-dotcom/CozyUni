# CozyUni — Admin Commerce Tool Spec v1.0

Status: **IMPLEMENTATION SPEC / INTERNAL ONLY**

Purpose: give operators enough tooling to support purchases/refunds without ever editing a wallet balance directly.

---

## 1. Core rule

There is no `Set balance = X` control.

All operator mutations create explicit compensating ledger events with actor, reason, and audit record.

Historical Apple transaction/ledger rows are never edited by an admin UI.

---

## 2. Roles

### `support_readonly`
May:
- search account;
- inspect wallet/ledger;
- inspect entitlements;
- inspect Apple transaction state;
- inspect notification/reconciliation status.

May not mutate anything.

### `commerce_operator`
Includes readonly plus:
- create support bonus grant up to **500 CC per action**;
- max **1,000 CC support grants per account per UTC day**;
- retry reconciliation/outbox job;
- revoke own unprocessed support grant only through compensating adjustment workflow;
- add internal support note.

Cannot:
- disable account;
- create negative manual balance adjustment;
- alter Apple refund status;
- exceed caps.

### `commerce_admin`
Includes operator plus:
- support grant up to **5,000 CC per action**;
- disable/re-enable Commerce Account;
- create explicit corrective debit/credit adjustment;
- clear a terminal dead-letter job after documented resolution;
- force Apple transaction reconciliation;
- revoke a cosmetic entitlement with reason when support/legal action explicitly requires it.

Admin cannot rewrite/delete ledger history.

---

## 3. Search

Admin search accepts exactly these identifiers:
- Commerce Account UUID;
- app account token UUID;
- Apple transaction ID;
- Apple original transaction ID;
- App Store notification UUID;
- catalog purchase UUID.

Do not support free-text search over email/name because commerce v1 does not store those fields.

---

## 4. Account overview

Show:
- account ID;
- status active/disabled;
- app account token;
- created time;
- last commerce activity;
- purchased CC;
- bonus CC;
- refund debt CC;
- wallet revision;
- total lifetime Apple-granted CC;
- total lifetime bonus/support grants;
- total CC spent;
- count of owned entitlements;
- count of refunded transactions;
- reconciliation warnings.

Never show raw access/refresh tokens.

---

## 5. Wallet ledger view

Chronological table:
- ledger ID;
- timestamp;
- event type;
- bucket;
- signed delta CC;
- source type;
- source ID;
- related ledger row;
- actor if admin event;
- request/ticket reference;
- metadata summary.

Expandable detail may show spend allocations by credit lot.

Default order: newest first.

CSV export available to `commerce_admin` only.

---

## 6. Apple transaction view

Show:
- transaction ID;
- original transaction ID;
- product ID;
- mapped CC amount;
- environment;
- purchase date;
- latest signed date;
- app account token;
- Commerce Account;
- delivery status;
- refund/revocation status/reason/date;
- related credit lot;
- related ledger rows;
- related notification UUIDs;
- JWS hash.

Raw JWS view is hidden by default and restricted to `commerce_admin` diagnostics.

Action:
`Reconcile with Apple`

This action:
1. calls App Store Server API Get Transaction Info;
2. verifies returned signed transaction;
3. sends result through the normal idempotent transaction update path;
4. adds admin audit event;
5. never directly toggles refund/delivery state.

---

## 7. Support bonus grant

Form fields:
- account ID (locked from current account page);
- amount CC;
- reason category;
- free-text internal reason minimum 10 chars;
- external support ticket/reference optional but strongly recommended;
- idempotency key generated by admin frontend.

Reason categories:
- `PURCHASE_DELIVERY_SUPPORT`
- `SERVICE_OUTAGE_COMPENSATION`
- `CATALOG_ISSUE_COMPENSATION`
- `GOODWILL`
- `INTERNAL_TEST_SANDBOX`

Production rejects `INTERNAL_TEST_SANDBOX`.

Grant behavior:
- if account has refund debt, grant repays debt first;
- only remainder becomes bonus lot;
- result preview must clearly show `debt repaid` and `new spendable` before final confirmation.

Confirmation requires typing `GRANT` or equivalent deliberate confirmation.

---

## 8. Corrective admin adjustment

`commerce_admin` only.

Use only when ledger/reconciliation incident cannot be corrected from Apple source events.

Fields:
- signed CC amount, non-zero;
- adjustment category;
- incident/ticket reference required;
- detailed reason minimum 20 chars;
- affected source reference if known.

Categories:
- `DATA_REPAIR`
- `DUPLICATE_EXTERNAL_EVENT_COMPENSATION`
- `LEGAL_SUPPORT_ADJUSTMENT`

Rules:
- never edit prior row;
- append `admin_adjustment` ledger row;
- negative adjustment may not make normal spendable lot balance negative;
- if required negative amount exceeds remaining credits, excess becomes refund-style debt;
- every adjustment records actor and before/after projection.

---

## 9. Account disable

`commerce_admin` only.

Disable blocks:
- new Apple claim delivery to this account;
- catalog spending;
- support grants from operator role.

It does not:
- erase wallet;
- erase entitlements;
- erase transaction history;
- block local board games.

Required reason + incident reference.

Re-enable is a separate audited action.

---

## 10. Entitlement tools

Show owned catalog items with:
- acquisition date;
- catalog purchase ID;
- charged CC;
- source spend ledger;
- revoked state.

Manual entitlement revoke:
- `commerce_admin` only;
- requires reason/ticket;
- does not automatically refund CC;
- if compensation needed, perform separate explicit support grant.

This separation keeps audit intent clear.

---

## 11. Notification inbox

Filters:
- received/processed/needs_reconciliation/failed;
- notification type;
- environment;
- time range;
- transaction ID.

Show:
- notification UUID;
- type/subtype;
- signed date;
- receive date;
- transaction ID;
- processing status;
- attempt count;
- safe error summary.

Actions:
- retry processing for retryable status;
- reconcile related transaction;
- mark operator note.

No action to mark an invalid JWS as valid.

---

## 12. Outbox/dead-letter view

Show:
- event type;
- created/available time;
- attempts;
- last error;
- locked worker;
- completed/terminal status.

Operator may retry retryable jobs.
Admin may clear terminal dead-letter only after adding resolution note.

---

## 13. Reconciliation dashboard

Counters:
- projection mismatch accounts;
- Apple transaction rows needing reconciliation;
- notifications failed/retryable;
- refund debt accounts;
- unprocessed consumption requests nearing deadline;
- duplicate-event attempts blocked;
- StoreKit claim error rate last 24h.

Any non-zero projection mismatch is RED severity.

---

## 14. Audit trail

Every admin mutation writes `admin_audit_events` with:
- actor ID;
- role;
- action;
- target account;
- request ID;
- source/ticket reference;
- reason;
- before summary;
- after summary;
- UTC timestamp.

Audit events are append-only.

---

## 15. Production safety

Production admin UI must:
- require authenticated staff identity;
- require HTTPS;
- use least privilege roles;
- automatically expire sessions;
- require re-authentication for `commerce_admin` destructive/corrective actions where identity provider supports it;
- never expose App Store private keys;
- never run arbitrary SQL;
- never contain a generic JSON-to-ledger endpoint.

---

## 16. Sandbox tooling

Sandbox admin page may additionally:
- show sandbox-only test accounts;
- clear sandbox account by creating a new isolated test account;
- display StoreKit sandbox transaction IDs;
- run scripted QA scenarios.

Sandbox-only actions must be compiled/configured out of production deployment.

---

## 17. Required admin QA cases

- operator grant under cap succeeds;
- operator grant above cap rejected;
- daily cap enforced under concurrent requests;
- admin adjustment produces ledger + audit row;
- no admin action directly edits historical ledger;
- Apple reconcile duplicate safe;
- disabled account cannot spend;
- sandbox-only action unavailable in production;
- raw tokens/secrets never rendered;
- CSV export restricted to admin.
