# CozyUni — Game Design Audit — 2026-10-01

Status: **audit completed / gameplay GDD gaps closed for v1**

## 1. Audit conclusion

The previous five game documents were **not implementation-safe full GDDs**. They were strong concept/pitch specs but still contained enough open language that an implementation agent would have to invent behavior.

Typical previous ambiguity included:
- `test 3 vs 4 pieces`
- `candidate rule`
- `optional later`
- vague HUD descriptions
- no exact pre-match screen flow
- no exact tutorial scripting
- no exact disconnect/forfeit behavior
- incomplete match-end ranking/tiebreakers
- unresolved event/economy constants
- unclear placement confirmation / input-lock behavior
- no authority rule telling an agent what to do when docs are silent

That level was acceptable for ideation, not production.

## 2. Audit standard

For current production, a game is considered design-complete only if an agent can implement a deterministic vertical slice from app entry to rematch without choosing gameplay behavior on its own.

Required categories:

| Area | Required |
|---|---|
| Start Game | screen content, actions, mode selection |
| Setup | players, avatars, sides/colors, presets |
| Lobby | host/ready/start ownership |
| Tutorial | exact sequence and required actions |
| Gameplay | exact canonical rules/constants |
| State machine | legal input states and resolution order |
| HUD | persistent/context UI and action priority |
| Camera | allowed framing/rotation/zoom behavior |
| Feedback | legal/invalid/action feedback |
| Pause/Settings | exact available controls |
| Room failure | reconnect and forfeit result |
| Match end | deterministic end condition |
| Final Results | rank/score/end reason |
| Ties | complete tiebreaker chain or shared rank |
| Rematch | reset/side/start-player behavior |
| Persistence | exact stats allowed |
| Assets | essential AI→3D kit vs engine/UI art |
| Scope | explicit non-features |
| QA | acceptance tests |

## 4. Authority hierarchy

For game implementation:

1. `docs/games/00_SHARED_GAME_EXPERIENCE_LOCK.md`
2. selected `docs/games/0X_*.md` full GDD
3. `docs/GAME_MODE_ROADMAP.md` for order/context only
4. other product/world docs
5. old code/comments

Higher source wins on conflict.

If the GDD is silent: **stop and raise a design question**.

## 5. Remaining specifications that are intentionally separate

These are not permission for implementation agents to invent final behavior. They require separate specs when their production milestone begins:

- exact network transport/backend technology
- account/auth implementation
- telemetry event naming/schema
- localization final copy for every language
- final audio asset catalog
- final visual component pixel measurements/style tokens
- store/IAP/monetization
- bots/AI opponents
- persistent Animal-Crossing-like CozyUni world

Temporary engineering placeholders may be used only when they do not alter locked rules or player-visible production behavior.

## 6. World audit decision

Do not build the world now.

The existing asset library is not discarded. It is reserved for a future world whose design target is a **real living life-sim layer**, not a decorative launcher.

When that milestone starts, it needs its own full design lock covering at minimum:
- player day loop
- world map/regions
- NPC schedules/behavior
- shops/interactions
- activities
- progression
- collectibles
- economy
- seasonal state
- travel
- save state
- multiplayer/social boundaries
- HUD/tutorial/settings

Until then, game production remains independent of the world.

## 7. Production recommendation after audit

Do not start all five games.

Production should now start with **Cozy Ludo only** and implement against the locked GDD from Start Screen through Final Results/Rematch.

The first implementation milestone is successful only when the agent no longer needs verbal clarification to complete an ordinary match flow.
