# CozyUni — Game Design Audit — 2026-10-01 — Local-First Revision

Status: **audit updated / current production scope clarified**

## 1. New scope decision

The earlier GDD set attempted to specify both:
- local multi-user play on one device
- future multi-device Room Mode

That was too broad for the first production milestone.

Current decision:

> **Build and polish local multi-user play on one tablet first. Multi-device networking is deferred.**

This removes a major source of engineering/design ambiguity before the first game is proven fun.

## 2. Current authoritative app flow

Defined in `00_APP_SHELL_FLOW_LOCK.md`:

```text
APP LAUNCH
 -> GAME LIBRARY
 -> select game
 -> GAME START SCREEN
 -> PLAY
 -> LOCAL PLAYER SETUP
 -> MATCH SUMMARY
 -> TUTORIAL if needed
 -> COUNTDOWN
 -> MATCH
 -> FINAL RESULTS
      -> REMATCH
      -> CHANGE PLAYERS
      -> GAME LIBRARY
```

There is no current Mode Select, Create Room, Join Room, QR, matchmaking or network-reconnect flow.

## 3. Game-selection clarity

The app now has an explicit main screen rather than an assumed shell:
- CozyUni header
- Settings
- horizontal game-card rail
- each card shows key art, title, local player count, expected time, category tag
- tap whole card -> selected game's Start Screen
- only games included in current build are shown

This closes the previous gap: `How does a player open the app and choose a small game?`

## 4. Shared local game flow

`00_SHARED_GAME_EXPERIENCE_LOCK.md` now locks:
- local player slot conventions
- Match Summary
- tutorial persistence
- countdown
- gameplay HUD hierarchy
- input-state vocabulary
- pause/restart/leave
- settings/accessibility
- result screen
- rematch/change players/game library
- local stats
- no-invention/change-control

## 5. UI layout

`00_SHARED_UI_LAYOUT_LOCK.md` now includes exact layouts for:
- Game Library
- Game Start
- Local Player Setup
- Match Summary
- gameplay HUD
- tutorial
- pause/settings
- Final Results

Network/mode-selection UI is explicitly forbidden in current v1.

## 6. Individual GDD scope

Current game GDDs are local-first:
- G1 Cozy Ludo: 2–4 local
- G2 Cozy Caro: 2 local
- G3 Cozy Journey: 2–4 local
- G4 Cozy Chess: 2 local
- G5 Cozy Tycoon: 2–4 local

Each game keeps exact rules, tutorial, HUD, result/ranking and acceptance tests.

## 7. Production authority hierarchy

Implementation agents read:
1. `00_APP_SHELL_FLOW_LOCK.md`
2. `00_SHARED_GAME_EXPERIENCE_LOCK.md`
3. `00_SHARED_UI_LAYOUT_LOCK.md`
4. selected game GDD
5. this audit
6. roadmap/product docs
7. old code/comments

If a behavior is still missing after those sources: stop and raise a design question.

## 8. Multi-device status

Multi-device is not cancelled. It is a later milestone.

It requires its own design/engineering lock before implementation:
- Create/Join Room UX
- authority model
- transport
- action/revision protocol
- reconnect/host loss
- failure states
- security/privacy

No speculative network code is required in the local milestone.

## 9. World status

World remains deferred.

Existing asset library is preserved for a later genuine Animal-Crossing-like life-sim layer.
Do not build a decorative launcher world.

## 10. Current production recommendation

Start only with **Cozy Ludo local single-device**.

The first vertical slice is complete only when:
- app boots to Game Library
- Ludo card opens Ludo Start Screen
- local 2/3/4 player setup works
- tutorial works
- complete match works
- Final Results/ranking works
- Rematch works
- Change Players works
- returning to Game Library works
- no network feature is required or exposed

After that, validate gameplay/pacing before adding the second game.
